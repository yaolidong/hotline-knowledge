## 修复内容

- **引用原文片段**：模型可返回 `span_id`；服务端绑定输入中已知的原文、chunk ID 与偏移。保留旧版 quote 格式兼容。唯一匹配且非空白字符完全一致时恢复原文空格/换行，并保存修正记录；同块中相接或重叠的真实引文可以合并，不能跨过未引用文字。不接受语义近似、标点替换、改数字或 OCR 自动纠错。最终仍使用原有严格 Schema 校验。同一三元组重复出现时合并全部证据，保留规范化日志；反馈重试一次指出多个错误实体。
- **逐块持久化**：每块结果、输入指纹、错误和聚合后的已校验实体关系写入现有 SQLite JSON 字段。一个块失败后继续其他块；整块失败时不删掉其中错误事实来制造“成功”。结构可解析但未通过校验的模型候选单独保存为 candidate，只供维护人员查看，不混入 extraction 或图谱。
- **失败恢复**：页面提供“重试失败块”。同一版本复用已解析正文和输入指纹匹配的成功块；缓存结果仍重新校验。PARTIAL/FAILED 且 DRAFT 才允许恢复，版本过期、同文档并发任务或权限不足拒绝操作。改变解析方式应创建新版本。
- **真实 PDF 表格**：pdfplumber 0.11.4 保持与现有 KAG 的 pdfminer.six 版本兼容，未升级核心依赖。对原生有边框表格保存行列、合并跨度、单元格原文和页面框，包含“标题 | 长段正文”的单行表格；表格外文字保留。多页表格在阅读器中的偏移修正为页起点加页内偏移。依赖锁重新解析，仅新增 pdfplumber，原锁定版本未改变；pip check 通过。
- **状态边界**：PARTIAL 可以查看成功部分和失败块原文，不可审核、修改或发布。READY 仅说明各块通过自动校验，仍需业务审核，不证明召回完整或语义正确。

## 仍需核对

扫描表格仍保留 OCR 文本和行框，尚未恢复可靠的行列结构；OCR 的公式符号错误不会因引文能定位就自动变正确。PDF 的开放边框、跨页单元格及流程图箭头拓扑不保证恢复。复杂材料条件的语义完整性、事项与证照区分、同名不同断言仍需要原文审核。CSV 目录使用原有独立逐行映射流程，未接入此次分块恢复接口。

黎平仍失败的 7 块已保存错误与未验证候选，包括 `RequiredMaterial → BASED_ON → LegalBasis` 超出当前端点约束、法规名称只引用后半段、概括后的 content/channel_type 不能逐字对应引文等。没有自动扩大 Schema、拼接缺失证据、删除错误事实或批准不完整资料来通过验收。恢复接口可在修正模型/Schema 配置后继续验证；更新解析规则应再建新版本。此报告不声称复杂文件抽取已达到生产级完整率。
