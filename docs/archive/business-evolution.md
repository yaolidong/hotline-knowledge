# 目录、更新与受限推理实施记录

2026-11-04。接续 [第一批事项工作台](../business-workbench.md)。当前仍为 OpenSPG/KAG 模块化单体；保留既有发布图和历史证据，未执行数据库结构迁移或上游依赖升级。

## 已落地的业务入口

1. **数据导入 → 结构化事项目录**：上传 CSV，读取样例后确认名称、编码、地区等列映射。Excel 需导出 UTF-8 CSV，暂未直接支持 XLSX。每批最多 50 条、40 列、同一实施地区，编码必须非空且批内唯一。混区和重复编码在创建任务前拒绝。
2. **审核与维护 → 版本差异与影响**：默认对比此前已发布版本；可明确指定同空间其他文件。分别显示原文、实体、属性、逻辑和关系差异，读取真实图查找需复核的同名事项。重抽取、重解析、原件变化分开标注；差异不自动建立政策修订、废止或替代关系。
3. **逐项质检处置**：表单选择“证据确认 / 误报 / 暂不能确认”，逐项说明理由；未确认不能通过。真实错误应先修正，修改仍使原审核失效。处置随审核写入 audit。为兼容旧调用，旧 `acknowledged_issues` + 总体审核说明仍可用，并明确记录 `legacy_acknowledgement`；新 UI 使用 `issue_resolutions`，一旦传入就必须完整覆盖本次问题且不存在 unresolved。
4. **事项工作台 → 依据路径 / 条件核对**：查看图中实际存在的依据关系，每条边可打开原文；明确条件按 TRUE/FALSE/UNKNOWN 核对。未知不作为不符合，不输出申请人是否具有行政资格。
5. **运营概览**：当前空间的任务/知识版本状态、最近 1/7/30 天已记录请求的状态分布和 p50/p95。只读，不自动重跑、发布或修改数据。

## 数据与检索约束

- 原 CSV 以原始字节保存并计算哈希；每条事项独立文本块，保留表头、数据行号、CSV 物理行终点和单元格偏移。多行单元格按 CSV 规则读取，原件可下载，阅读器可对照列名和单元格。映射改变会生成独立来源任务，默认映射字段为空时维持旧文档去重指纹。
- 每行调用既有 Extractor/KAG 模型、规范化和 Schema 校验。映射出的事项名称、编码、费用、期限、主体等与抽取值冲突则失败，不静默覆盖。明确字段可补齐事项、实施地区和部门关系，但仍为 DRAFT，并记录原单元格证据。目录列应定义单个实施主体；复杂多部门/基本事项与实施事项体系仍需接入方明确数据契约。
- 同名、同地区、不同编码的事项保留不同实体。客服先确认具体编码；目录原文在进入关键词、向量和模型上下文**之前**按选中事项行过滤，不能把同表其他事项送给模型再期待模型自行排除。
- 每次新构建追加 BUILD_PROFILE，保存来源哈希、Schema 哈希、解析/抽取/规范化代码哈希及模型名称。旧记录不会补造历史指纹；此记录也不意味着远端模型权重已被固定。
- 差异以类型和规范名称做候选对应。同名多实例标记歧义，不自动强配。改名可能表现为一项新增、一项本次未抽取；受影响事项是保守复核清单，不是已确认的法律适用变化。行数、差异展示和图候选均有上限并报告截断。
- 审核身份关联只在两端均已发布、内容指纹未变、同地区同空间时扩展**一层直接关联**。不传递 A=B、B=C，也不物理合并历史图。每次读取当前审计状态，撤销即时生效；生成期间撤销则丢弃本轮答案。检索结果保留关联事件编号和各自来源。
- 依据路径只提供固定 `legal_basis` 模板，最长 3 跳，最多 50 条；每跳检查 Schema 端点、发布范围、地区、原文明示日期和逐字引文。遇到查询上限会报告不完整。暂未接入 KAG 通用 solver，也不从图连通性推断新法规。
- 条件核对只接受当前规则中的叶子观察项，并校验整个规则/证据集合的哈希。来源存在差异、无明确规则或已停用时不核对。输出逐个条件表达式，不合并成“申请人合格”。目前时效约束仍以文档明示日期为主，未实现条款级修订传播。

## 接口

均使用现有 Bearer 认证。`Question` 兼容增加 `service_code`；其余空间参数沿用第一批。

| 接口 | 请求及权限 |
|---|---|
| POST `/api/import/directory/preview` | multipart `file`；admin/maintainer，返回字段、样例和建议映射，不建任务 |
| POST `/api/import/directory` | multipart `file`、JSON 字符串 `metadata`，其中 `directory_mapping` 为字段键→原列名；admin/maintainer |
| GET `/api/revisions/{rid}/changes?before={baseline}` | 维护/审核角色；只读差异，baseline 可空 |
| POST `/api/revisions/{rid}/review` | 增加 `issue_resolutions: {问题ID: {status,note}}`；既有权限及 expected_version 不变 |
| POST `/api/reasoning/paths` | Question + `plan: legal_basis`；已登录角色，只读真实图 |
| POST `/api/reasoning/conditions` | Question + 可选 `observations: {原文叶子: TRUE/FALSE/UNKNOWN}`、`rule_set_hash`；先空观察项加载，再用返回哈希提交核对 |
| GET `/api/operations/summary?space=production&days=7` | 维护/审核角色；当前版本状态、时间窗内最近最多 1000 条请求的 nearest-rank 分位数 |

目录字段键：`service_name`、`service_code`、`region` 必需；`department`、`fees`、`time_limit`、`applicants` 可选。其他原始列仍保留并参与该行 LLM 抽取。示例：[合成目录](../examples/synthetic_directory.csv)。不使用合成内容冒充权威事项目录。

## 验证及数据准备

- 完整离线/API/浏览器回归结果见 [验证记录](../verification.md)，图替身和模型替身测试不作为真实服务验收。
- `scripts/validate_directory_changes.py`：真实浏览器映射导入、DeepSeek 逐行抽取、OpenSPG/Neo4j 写入与回读、原单元格定位、DeepSeek QA、真实指南只读差异。报告位于 `test-results/directory-changes/`。
- `scripts/validate_reasoning.py`：真实合成别称目录抽取/发布、审核身份关联后扩展图查询与 QA、撤销、真实依据路径、三值核对与浏览器。验证结束撤销测试关联，原始实体与资料保留。报告位于 `test-results/reasoning/`。
- `scripts/prepare_evaluation.py <revision_id> ... --output <新文件.json>`：只读准备原文、哈希、块和区域标注包，使用 `PENDING_HUMAN_REVIEW`，不把模型输出预填为真值。当前已为真实食品指南两个版本生成 `test-results/annotation/food-guide-review-20261104.json`；它们是同一来源的两个系统版本，不能算两份独立政策样本。
- 用户确认继续食品经营许可范围后，新增固定来源的 25 项局部核对和 10 个真实接口回归，实际结果及边界见 [食品指南评测记录](food-guide-evaluation.md)。完整人工标注仍待业务复核，不能将该局部清单通过数当作整体准确率。

真实模型输出仍可能遗漏、误分实体或误解语义；证据逐字存在不能证明断言得到支持。当前没有业务人员复核的完整金标准，因此没有真实 Precision/Recall/F1、无依据回答率或生产吞吐指标。运营耗时只描述已经记录的请求，不含未记录异常，不能冒充负载测试。
