# 工作台设计与检查记录

2026-11-04 后续更新：客服页已改为连续对话、底部输入区与每轮证据侧栏；图谱增加 D3 布局、图例、邻接高亮及业务/来源显示切换。以下保留前次整体改版记录，当前新增模块与实际验证见 [对话与图谱更新](chat-and-graph.md)。

本次改版直接服务两类任务：客服快速得到有证据的答复；维护/审核人员对照原件确认知识。技术方案沿用 FastAPI 同源静态页面与原有 SVG 图谱，不引入第二个前端框架、外部字体或 CDN。

设计取舍依据用户授权“自行作出合理的工程选择”“保持专业、清晰、简洁，不需要重新设计整个开源项目视觉体系”：沿用蓝灰色与系统中文字体；导航固定，桌面采用适度紧凑的数据布局；窄屏将分栏改为上下排列。没有创建假统计、模拟政策、营销首屏或与数据库脱离的展示图。

| 工作区 | 布局与流程 |
|---|---|
| 客服查询 | 问题优先，地区/事项/日期辅助限定；直接答案和原文引用相邻；右侧提示核对范围，不重复堆叠操作控件 |
| 数据导入 | 文件和文本明确分开，来源元数据在同一表单；OCR 策略使用业务可理解的说明；旁侧显示后续流程与真实服务状态 |
| 抽取结果 | 服务端搜索和状态筛选，分页真实任务；打开资料后收起列表，让原件和知识占据主要空间 |
| 审核维护 | 原件与事实并排，引用同步定位；审核/发布独立，失败和未审核内容不会进入正式客服查询 |
| 知识图谱 | 检索工具、交互画布、详情面板；保留按需查询、缩放、拖动、全屏和原文入口 |

视觉令牌集中于 `style.css` 的 `:root`：正文、次要文字、主色、背景、边框、状态色、圆角、侧栏宽度。正文使用系统字体；图标为本地 SVG。字体和布局方向继承既有项目，没有新增品牌授权或第三方组件模板。

实际检查使用本地 Edge/Playwright 登录后操作，截图覆盖 1440×1100、820×1180、390×844；检查了正文、表单、侧栏、阅读器和审核双栏，断言页面无水平溢出。语义标签、表单 label、可见键盘焦点、跳转链接、对话框关闭、角色导航和错误状态有相应实现。阅读器栅格图片不提供 PDF 原生文字选择，因此单独提供可复制正文。

`light-frontend-design` 的共享对比度工具检查了 11 组关键前景/背景与控件边界，首次发现 3 处不足，已修正为全部通过。该结果不等同于全站 WCAG 认证。通用布局脚本中“导航必须单行且不超过 80px”的规则适用于横向网站导航，本项目桌面采用垂直业务侧栏，记录为不适用，不伪造高度数据使其通过。

补充执行技能的真实浏览器检查函数：375×812、768×1024、1440×900 均为 PASS，包括键盘可达、焦点、名称和溢出检查。检测时仅给无 ID 控件临时补充唯一定位符，避免工具将多个同类标签错误计为同一个控件，未改变可达性。静态外观检查 CLEAN；通用布局检查为 6/7，综合交付模板如实保留 R5 导致的 FAIL，因此未声明该模板的 READY。这一通用模板结果与已通过的实际业务验收分开记录。

证据位于 `test-results/ocr-ui/`：各视口截图、`report.json`、`design-tokens.json`、`contrast.json`。截图使用真实测试项目数据，未将凭据写入截图或报告。完整 OCR、真实模型和数据操作的验证边界见 [OCR 验收说明](../ocr-and-workbench.md)。
