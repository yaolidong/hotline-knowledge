# 政务知识语义、证据与检索升级

日期：2026-11-04。沿用现有 OpenSPG/KAG、Neo4j、SQLite、原件阅读器与审核发布流程；未新增图类型或关系，未执行数据库结构迁移，也未覆盖已有已发布知识。

## 已实现

### 1. 实体与规则

`Entity.name` 保留原文提及，`canonical_name` 由服务端统一字形和中文断词空格，不扩写简称、不修正政策内容。`display_name` 只能来自原文片段。图节点名称使用规范名，已有 `metadata` JSON 保存原始名、展示名及步骤位置，原文引文保持逐字一致。

条件和材料节点均可保存 AND/OR/NOT。逻辑可附 `basis`，需要逐字出现在证据中且包含对应连接词；NOT 的肯定命题不能再次包含明显否定。该检查不构成完整语义蕴含证明。

新增受限、可追溯的规范化规则，只应用于新抽取结果：

- 纯主体类别且只有一条事项条件关系时，转为该事项的 `applicant_scope` 属性。原有 `applicants` 和两处证据都保留，转换记录包含原实体及目标 ID。有资格限定或其他关系时不改写。
- 仅含两个简单名词项的“甲或者乙”材料，生成带逐字依据的 OR。含额外并列、否定或条件的复杂语句继续待审，不以启发式推断完整逻辑。
- “办理流程：甲-乙-丙”等明示线性链保存为 `sequence_basis`，服务端计算步骤位置；不把推导位置冒充原文数字，不从段落排列推断分支流程。

`normalizations` 保存规则名称、版本和原文依据/对象，供审核对照。模型提供的该字段会清除，由服务器重新生成。抽取还提供一次有上限的语义问题反馈；不能保证模型修正所有问题。

审核页集中展示事项/证照混淆、主体误分类、缺失逻辑、材料形式适用范围、步骤顺序和未关联要求等提示。新版草稿 `schema_version=2` 审核通过前必须逐项勾选确认，并填写审核说明；确认项保存于审计事件。旧版数据仍可读取，质检通过也不代表已经证明材料与条件完整。

### 2. 原件区域定位

`evidence.py` 根据版本、块内偏移和保存的版面信息生成 locator，包含原件 SHA-256、版本、页码、区域、解析版本等。坐标以渲染后的页面左上角为原点，宽高归一化。

- OCR：按偏移匹配行框，修复相同文字重复出现时仅凭文本包含关系错误高亮的问题。
- 原生 PDF：使用已安装 PDFium 精确查找唯一文字行并转换坐标，支持页面旋转；重复或无法匹配的文字不猜位置，保留文本定位。
- DOCX：保留表格编号、逻辑行列及单元格文本范围。阅读器显示表头和相邻单元格，并高亮具体命中单元格。该视图是解析结构，不冒充原始 Word 排版或 DOCX 页码。

原件、解析文本及区域接口继续鉴权。客服只能读取 PUBLISHED。旧版无原生 PDF/表格区域元数据时保留文本定位，显式重新处理才产生新区域数据。

### 3. 跨文档身份审核

审核页每个实体提供“跨文档实体关联”。候选只在同地区、同类型中比较名称、明示别名和编码；编码/层级冲突排除。候选最多扫描 200 个其他文档版本，展示前 20 项并报告截断。

管理员/审核员可填写依据确认、撤销；维护人员可看候选，客服不能访问这些维护接口。使用现有 audit 表追加 IDENTITY 事件，含双方指纹和乐观并发校验。修改来源、拒绝或停用使原关联失效，撤销不删除历史。

这是一份独立的身份审核账本，不是 Neo4j 节点的物理合并，也不把身份确认扩展为政策要求一致。条件、材料与步骤不参加通用身份合并；问答仍根据各来源的发布状态、地区和时间检索事实。

### 4. 问题范围与混合检索

支持问题中的明确完整日期；年份、去年、多日期、无效日期或与日期控件冲突时要求澄清。紧接“发布/印发/的文件”等表达的日期不自动作为业务查询日期。尚不是通用时间语言理解器。

保留原有地区层级和真实图事项候选机制；问题明确提到另一事项、但界面仍选择旧事项时要求重新确认。界面显示本轮实际采用的日期。

`embedding.py` 复用已部署的本地 BGE 嵌入服务，使用现有 OpenAI SDK 调用。锁定的 KAG `OpenAIVectorizeModel.vectorize()` 异常分支会记录完整输入，因此此处使用脱敏错误适配，不修改上游代码。

原文先按 PUBLISHED、事项、地区、明示时间范围过滤，再进行关键词与向量召回，使用 RRF 融合排序。全部图事实命中块为必留证据，加上融合排序前 8 块及前后块；超出上下文上限明确要求缩小范围，不静默截去材料或例外。相关性分数不作为真实性或审核分数。

缓存位于忽略目录 `data/embeddings`，键包含模型地址、名称与文本散列，文件仅保存向量。默认最多 500 个候选块、2048 个索引窗口。服务不可用或达到上限时显式回退到图谱与关键词检索。若相同模型名称对应的权重变更，应使用新模型标识以隔离旧缓存。

## 配置与部署

Compose 为既有 embedding 服务增加 `127.0.0.1:8090` 端口，继续使用原令牌鉴权。应用配置：

```dotenv
HOTLINE_EMBEDDING_BASE_URL=http://127.0.0.1:8090/v1
HOTLINE_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
HOTLINE_EMBEDDING_API_KEY=<本地嵌入服务令牌>
```

未配置上述服务时，原有图谱与关键词查询继续运行。`scripts/configure_local_embedding.py` 可复用 `deploy/images.env` 中的本地服务凭据，先执行真实嵌入请求，再备份并更新项目 `.env`；不修改系统环境变量、不打印令牌，也不覆盖已有外部嵌入地址。本机真实返回维度为 512。

图 Schema 的类型、关系和物理属性保持兼容。新增语义放在现有 attrs/rule/metadata JSON；SQLite 继续使用原表，身份事件追加到 audit。禁止为了升级批量重写历史图。已发布指南的新抽取结果必须作为新草稿复核。
