# 对话查询、图谱探索与 Schema 扩展

本次改动集中于前端，不改变 `/api/qa`、`/api/query`、`/api/graph` 接口、审核规则、图数据或 OpenSPG/KAG 上游源码。

## 图谱探索

延续本地 SVG 画布和缩放/拖拽控制，加入 D3 力导向/环形布局、类型图例、邻接高亮和属性面板。同端点关系采用弯曲连线，类型字标和方向箭头辅助阅读。每页最多 60 节点，静态布局只计算有限步数，不运行持续动画。

默认显示业务节点；勾选“来源节点”显示已加载的 SourceDocument/Chunk 及来源边。上方统计当前显示数量，下方统计后端本次返回数量；隐藏仅影响视图，不删除数据。视口尺寸变化保留缩放比例和中心，窄屏可平移探索或“适应画布”。保留全屏、邻域查询、阅读/下载原件。

视觉组织参考 [Neo4j Bloom 的画布、图例与详情](https://neo4j.com/docs/bloom-user-guide/current/bloom-visual-tour/bloom-overview/)，布局复用 [D3 forceSimulation](https://d3js.org/d3-force/simulation)，核查日期 2026-11-04。未复制其品牌或专有实现。

`d3-force-bundle.js` 顺序拼接 d3-dispatch、d3-quadtree、d3-timer、d3-force 官方压缩文件，均固定 3.0.1，约 17 KB。取得时核验了 npm tarball SHA-512；版本、来源及 bundle SHA-256 在 `d3-manifest.json`，ISC 许可在 `d3-LICENSE.txt`。运行时只加载同源文件，不访问 CDN。

## 客服对话

连续消息、底部输入区、右侧证据栏；支持 Enter 发送、Shift+Enter 换行、新对话、停止等待、失败重试、复制含提醒和引文的答复。窄屏通过“查看依据”展开来源，也可点击引用打开原件。

1. 明确地区、事项并输入来电问题。
2. 每轮独立检索已发布图谱和原文，保存该轮范围、答案与引用。
3. 检索到唯一事项时回填可见范围控件；可继续问材料、条件、渠道等同事项问题。折叠后仍显示范围摘要。
4. 更换业务请修改范围或新建对话。历史轮的“查看依据”可回看对应引用。
5. 阅读原件，核对条件、例外和时效后答复。

这是**显式范围内的连续查询**，不是任意历史语义解析或跨业务自动消歧。服务器保持无会话接口，旧答案不作为新证据。每页最多 40 轮，刷新、退出或新对话后清空；不发送聊天历史，不写入 localStorage/sessionStorage。停止等待中止前端请求，但不能保证后台模型停止计费，页面明确说明此边界。没有伪流式输出或虚构进度。

## Schema 是否固定

Schema 是明确约定的领域模型，**可以维护扩展，但模型不能自行新增类型**。唯一手工维护的定义是 `hotline/config/schema.json`；提示词、校验、OpenSPG DSL、前端选项和关系标签均复用它。

| 当前类型 | 表达的知识及常见属性 |
|---|---|
| PolicyDocument 政策文件 | 法规、公文、通知；文号及发布/施行/失效/废止日期 |
| PolicyProvision 政策条款 | 条款编号、正文 |
| GovernmentDepartment 政府部门 | 发布、主管、受理部门；层级、地址、电话 |
| ServiceItem 政务事项 | 许可等事项；编码、时限、费用、适用对象 |
| EligibilityCondition 办理条件 | 申请与排除条件；正文及 AND/OR/NOT 规则 |
| RequiredMaterial 申请材料 | 份数、形式、要求 |
| ProcedureStep 办理步骤 | 申请、受理、审核等；顺序与内容 |
| ServiceChannel 办理渠道 | 线上/线下渠道；网址、地址、类型 |
| AdministrativeRegion 行政区划 | 区划代码、层级 |
| LegalBasis 政策依据 | 法律、法规或条款；文号、编号、引用内容 |

共 10 类领域实体、14 类业务关系，另有两个来源系统类型与两类来源关系。补贴项目、申请群体、机构职责等可按查询需求扩展；日期、费用、份数通常先用属性，避免每个字段都建节点。全部知识必须绑定原文证据。

扩展流程：修改配置及标注回归样例 → `python -m hotline.cli schema --output data/Hotline.proposed.schema` 离线生成/校验 → 比较已有类型 → 隔离项目验证 → 制定迁移、审核并部署。`schema --apply` 仅支持空专用项目创建类型，不提供已有项目自动迁移；不能仅修改 JSON 后重启就宣称图模型升级完成。新增查询意图、复杂规则语义还需代码和测试；历史知识不会自动获得新字段。
